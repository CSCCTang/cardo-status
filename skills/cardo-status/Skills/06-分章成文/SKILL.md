# 06 分章成文

## 用途
按章节映射从源报告“取料成文”，生成 A–F 六章初稿：只搬运原报告表述与数字，
每节附来源行，无来源的节落“缺项-<章><序号>”，并汇总本节缺项表。

## 单独运行
```powershell
python Skills/06-分章成文/scripts/gen_chapters.py ^
  --template-outline 过程文件/03-模板与源报告转储/模板转储/<模板>.outline.json ^
  --source-dump 过程文件/03-模板与源报告转储/源报告转储 ^
  --mapping 过程文件/04-章节映射/章节映射.yaml ^
  --materials 过程文件/01-建档与材料归集/分类清单/分类清单.json ^
  --facts 过程文件/05-事实抽取与事实库/facts/事实库.json ^
  --out 过程文件/06-分章成文/分章初稿 [--gap-mode]

# 单章自检由 06 引擎统一执行，--unit 选本章判据（本章契约在对应章节 skill 的 规则/章节契约.yaml）
python Skills/06-分章成文/scripts/check_chapter.py ^
  --unit C --project-dir . --draft 过程文件/06-分章成文/分章初稿/C_现状详细分析.md ^
  --direction 老旧街区 --out 过程文件/06-分章成文/自检/C.json
```

## 章节 skill（按 A→F 顺序逐章过闸门）
| 单元 | skill | 对应章 |
|---|---|---|
| A | `06-A-项目概述` | 项目概述 |
| B | `06-B-片区基础概况分析` | 片区基础概况分析 |
| C | `06-C-现状详细分析` | 现状详细分析 |
| D | `06-D-核心问题汇总` | 核心问题汇总 |
| E | `06-E-现状综合研判与更新思路` | 现状综合研判与更新思路 |
| F | `06-F-附件` | 附件 |

## 输出
- `分章初稿/A_项目概述.md … F_附件.md`。
- 每章含：H1、模板 H2、来源行（`（数据来源：…）`）、本节缺项表、来源映射。
- `自检/<章>.json`（`checks[]`，level=FAIL/WARN/PASS/INFO/SKIP）。

## 结构约定
- H1 只取到第一个 H2 前，避免整章重复搬运；H2/H3 取到同级或更高级标题前。
- 源报告自带 `（数据来源：…）` 行会被过滤，重写为统一来源行。
- 建筑节固定前置“建筑安全、历史风貌与合规性”框定句。
- D 章按源报告问题小节成文；无源则用 8 个固定小节。F 章生成附件一~三（缺口版的附件四只出「数据缺口索引」一页，指向 数据缺口清单.xlsx）。
- **结论优先（v2）**：无源节不得留空、不得写「资料缺失」——给「初步判定（推断依据＋置信度）」，
  缺口只进《数据缺口清单.xlsx》；D 章每类问题写全五要素（表现/证据或推断依据/成因/影响/对应更新方向）。

## 退出码
`gen_chapters.py` 0 成功；2 参数错误。统一自检 `scripts/check_chapter.py` 0 通过（WARN 不算失败）；1 有 FAIL；2 输入错误。
pipeline 的阻断集：`CHK-HEAD-1/2/3`、`CHK-LEN-1/2`、`CHK-GAP-3`、`CHK-PROC-1`、`CHK-BAN-1/2`；
缺口版下 `CHK-LEN-1/2` 降为提示级。

## 已知限制
- 不做同义改写与扩写，内容密度受源报告覆盖度约束。
- B 章证据数、D/E 章 S 编号等在部分项目属提示级失败，需在交付说明解释。
