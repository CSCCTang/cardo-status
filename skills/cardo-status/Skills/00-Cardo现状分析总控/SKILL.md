# 00 Cardo 现状分析总控

## 用途
把 01–09 九个技能按门禁顺序串起来，**一步一步写好现状分析报告**。
只做编排、门禁与状态留痕，不写入任何事实、不补数字。

## 执行原则
1. 严格按 01 → 02 → 03 → 04 → 05 → 06（A→B→C→D→E→F 六章）→ 07 → 08 → 09 顺序执行。
2. 每步：读上一步产物 → 执行命令 → 核对门禁 → 写留痕；不通过就停，不跳步。
3. 缺什么在对话里说明，并给替代方案，不自行补数。

## 入口
```powershell
python Skills/00-Cardo现状分析总控/scripts/pipeline.py run --workspace .           # 全量九步
python Skills/00-Cardo现状分析总控/scripts/pipeline.py run --from 06 --to 08       # 区间续跑
python Skills/00-Cardo现状分析总控/scripts/pipeline.py status --workspace .        # 状态与交付物
python Skills/00-Cardo现状分析总控/scripts/pipeline.py scaffold ...               # 复制技能、建新工作区
```

## 工作区参数
`工作区参数.json`（schema `cardo/workspace-params/v1`）必需字段：
`project`、`direction`、`template_file`、`source_report`；`delivery` 默认 `输入文件`。

- **模板**：`template_file` 指向根目录 `提资数据/模板/`（相对路径，如 `../提资数据/模板/xxx.docx`），不再放进 `输入文件/`。
- **源报告与材料**：`输入文件/` 是投递区，用户可放文件、文件夹或 zip；01 会先解包 zip 再归集。
- 原件只读：01 结束时核对投递区顶层原件 sha256 未变。

## 逐步操作卡

### 01 建档与材料归集
- 先解包 `输入文件/*.zip` → `输入文件/解包-<名字>/`，再递归归集。
- 产物：`过程文件/01-建档与材料归集/分类清单/分类清单.json`、`原件指纹.json`、`项目索引.md`。
- 门禁：分类清单有空值 → exit 3，请用户拍板，不猜测。

### 02 齐套检查与缺料拍板
- 产物：`过程文件/02-齐套检查与缺料拍板/齐套检查/材料齐套表.json`。
- 门禁：缺料选 `先出稿`（干净版继续，缺料按推断给初步判定）或 `先补料`（exit 3 停下等补齐）。

### 03 模板与源报告转储
- 输入：根目录模板 + `输入文件/` 里的源报告。
- 产物：`过程文件/03-模板与源报告转储/模板转储/`、`源报告转储/`。
- 门禁：模板 sha256 与章节契约一致；模板未替换。

### 04 章节映射
- 产物：`过程文件/04-章节映射/映射.yaml`、`人工确认.yaml`。
- 门禁：中等置信别名必须逐条拍板（`sources` 或 `sources: []`）；缺口比例只做提示，**不再自动升缺口版**（v2：默认干净版）。

### 05 事实抽取与事实库
- 产物：`过程文件/05-事实抽取与事实库/facts/事实库.json`。
- 门禁：事实必须能回溯到源报告或材料原文。

### 06 分章成文（引擎 + A–F 六个章节 skill）
1. `06-分章成文` 引擎按模板节点生成六章初稿到 `过程文件/06-分章成文/分章初稿/`。
2. 按 skill 顺序逐章自检，**一章不过不进下一章**：

| 单元 | 章 skill（契约与规则副本） | 自检命令（06 引擎统一执行） |
|---|---|---|
| A | `06-A-项目概述` | `python Skills/06-分章成文/scripts/check_chapter.py --unit A --project-dir . --draft <A_*.md> --direction <方向> --out 过程文件/06-分章成文/自检/A.json` |
| B | `06-B-片区基础概况分析` | 同上，换 `--unit B` 与 B 草稿 |
| C | `06-C-现状详细分析` | 同上，换 `--unit C` |
| D | `06-D-核心问题汇总` | 同上，换 `--unit D` |
| E | `06-E-现状综合研判与更新思路` | 同上，换 `--unit E` |
| F | `06-F-附件` | 同上，换 `--unit F` |

- 阻断项：`CHK-HEAD-1/2/3`、`CHK-LEN-1/2`、`CHK-GAP-3`、`CHK-PROC-1`、`CHK-BAN-1/2`；
  缺口版下 `CHK-LEN-1/2` 降为提示级。

### 07 表 3.1 口径计算
- 产物：`过程文件/07-表3.1口径计算/指标计算-*.json`、`表3.1.md`。
- 门禁：除零/单位不一致/占比超差即停；全缺项留空，不补数。

### 08 组装与模板渲染
- 产物：`成果文件/<项目名>现状分析报告.docx`。
- 门禁：必须出现 `[verify] ok`（标题/H1/H2/表格/样式/东亚字体/页面设置回读）。

### 09 三重自检与边界
- 产物：`回溯表.json`、`契约检查/`、`边界检查.json`、`数据缺口清单.xlsx`。
- 门禁：完整版契约 fail=0；缺口版 fail>0 须逐项写入验证报告与缺口清单；
  原件 sha 未变、模板 sha 一致、技能无绝对路径、交付物齐套。

## 输出
- `过程文件/00-总控/运行状态.json`、`运行日志.json`、`运行报告.md`、`项目索引.md`。
- `成果文件/`：现状分析报告.docx、输入材料补齐确认单.docx、数据缺口清单.xlsx。

## 退出码
| 码 | 含义 |
| --- | --- |
| 0 | 九步全部通过（完整版或缺口版） |
| 1 | 硬失败（结构性检查未过） |
| 2 | 参数/输入缺失（工作区参数不全等） |
| 3 | 需人工确认（分类待确认 / 映射待复核 / 缺料选择先补料） |

## 关键文件
- `scripts/pipeline.py`：唯一入口。
- `规则/门禁.json`：阻断项、缺口版放宽项、缺口比例阈值、回溯覆盖率下限。
- `记忆与规则/验证基线-CardoStatus.json`：首次运行生成，换机/改规则后用于 diff。

## 已知限制
- 章内自检的 WARN/提示级 FAIL（如 B 章证据数、D/E 章 S 编号）不阻断，验收以 09 契约与边界为准。
- 缺口版不是“完整报告”：所有缺项均登记，补齐资料后须重跑并用完整版口径验收。
